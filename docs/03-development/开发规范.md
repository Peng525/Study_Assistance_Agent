# 开发规范

> 版本：v1.0 | 日期：2026-08-23
> 适用阶段：Phase 0

## 代码规范

### 前端（React + TypeScript）
- 使用 TypeScript，不写纯 JS
- ESLint + Prettier 格式化
- 组件用函数式 + Hooks，不用 class 组件
- 状态管理用 Zustand（不用 Redux/Context 做全局状态）
- 流式请求用原生 fetch + ReadableStream（不用 React Query）
- 非流式请求用 React Query 管缓存

### 后端（Python FastAPI）
- Python 3.13+，类型注解必填
- async 优先（大模型 SSE 转发必须 async）
- SQLAlchemy 2.x 风格（不用 1.x 旧 Query API）
- 配置用 pydantic-settings 读 .env
- 密码用 bcrypt hash，API key 用 AES-GCM 加密

## Git 规范

### 分支策略
- `main` - 主分支，可运行状态
- `dev` - 开发分支（Phase 0 可直接在 main 开发）
- `feature/xxx` - 功能分支（如 `feature/subtitle-selection`）

### 提交规范（Conventional Commits）
```
<type>(<scope>): <subject>

<body>
```

type 列表：
- `feat` - 新功能
- `fix` - 修复 bug
- `docs` - 文档变更
- `style` - 代码格式（不影响功能）
- `refactor` - 重构
- `test` - 测试
- `chore` - 构建/工具变更

示例：
```
feat(player): 实现ArtPlayer自定义字幕渲染层
fix(chat): 修复SSE流式输出中断不清理状态的问题
docs(arch): 更新架构v2补充Whisper集成方案
```

### 提交门禁
- git commit 被 Hook1 拦截
- 需 `code-review-pass.flag` 和 `test-pass.flag` 两个标记都是 PASS
- 标记由各自 subagent 完成检查后写入
- 主 Agent 提交成功后清空标记为 PENDING

## 目录规范

### 业务源码（仅主 Agent 可写）
```
src/              # 前端业务源码
backend/          # 后端业务源码
```

### 测试文件（测试 Subagent 可写）
```
tests/            # E2E 测试
```

### subagent 临时产出（gitignore 忽略）
```
_scratch/         # subagent 产出，主 Agent 确认后提升到 docs/
```

### 正式文档（纳入 git）
```
docs/             # 项目全生命周期文档
```

## Subagent 权限铁律

- **业务源码（src/、backend/）修改权永远只在主 Agent**
- Subagent 发现问题写报告（_scratch/），不碰业务代码
- 代码检查 subagent 可写：`_scratch/*.md` + `.codebuddy/code-review-pass.flag`
- 测试 subagent 可写：`*.test.*` + `_scratch/*.md` + `.codebuddy/test-pass.flag`
- 标记文件不是业务源码，subagent 写标记不违反铁律

## 敏感信息

- API key、密码存 `.env`（gitignore 排除）
- `.env.example` 作为模板可提交
- 禁止在代码/文档/日志中硬编码 key 或密码
- 管理台列表显示 key 只显示后 4 位（`sk-****1234`）
- 启动日志严禁打印 key
