# Phase 0 范围变更说明（提议书 V1.2 → 升级后 Phase 0）

> 日期：2026-08-23
> 依据：需求评审报告 F1（范围错位）、用户多轮澄清
> 用途：附在提议书后作为 V1.3 变更说明，消除评审方与开发方的信息差

---

## 一、变更背景

提议书 V1.2 把 Phase 0 定位为"外部独立演示原型"——纯前端、预置固定素材、不碰真实场景、Token 超限属可接受局限。

经需求澄清，Phase 0 实际范围为"可直接拿来的最小可用版"——可换自备素材、管理台配置大模型、需要轻量后端、用户用真实长课程。

两者不是一回事。提议书所有"原型可接受"风险结论都建立在"演示中短课程样本"前提上，该前提在升级后失效，风险登记册需重做。

---

## 二、范围差异表

| 维度 | 提议书 V1.2 Phase 0 | 升级后 Phase 0 | 变更性质 |
|---|---|---|---|
| **定位** | 纯演示原型，不碰真实场景 | 可直接拿来的最小可用版，既评审又自用 | 根本性变更 |
| **素材** | 预置固定示例，不做文件上传 | 用户可换自备素材（视频+VTT/SRT字幕+课件） | 范围扩大 |
| **大模型 API** | 硬编码公有 API | 管理台后端配置（key/baseUrl/模型名） | 新增后端 |
| **后端** | 无后端，纯前端 | 需要轻量后端（管理台配置 + 架构师评估的存储） | 新增后端 |
| **课程长度** | 仅中短课程样本 | 用户真实课程（可能 1-2 小时） | 范围扩大 |
| **Token 超限** | 低风险/原型可接受 | **高/中高风险**——核心链路直接断 | 风险升级 |
| **字幕格式** | 仅标准 VTT | 至少 vtt + srt 双支持 | 范围扩大 |
| **播放器** | ArtPlayer.js 最小集成 | 参考B站/学习平台播放器形态的完整交互 | 范围扩大 |
| **交付对象** | 仅 B 站评审 | B 站评审 + 自用 | 范围扩大 |

---

## 三、明确推到 Phase 1+ 的功能（不变更）

以下功能在升级后 Phase 0 中仍然不包含，推到 Phase 1+：
- 视频上架流程
- 学习栏目分类
- 观看历史记录
- 视频上传功能
- 用户系统（登录注册、个人主页）
- UGC 平台属性（别人上架、用户看别人上架的）

---

## 四、影响波及

1. **风险登记册需重做**（见 `_scratch/风险登记册-v2.md`）——所有"原型可接受"项按真实使用场景重评
2. **架构需增加轻量后端**——管理台配置 + 素材读取 + 大模型 API 代理（架构师评估）
3. **交付物形态变化**——不再是"一个 H5 网页"，而是前端 + 轻量后端
4. **B 站评审方需知晓**——评审时拿到的交付物比 V1.2 描述的复杂，需提前对齐预期
