> 状态：待评审

## 变更项

### 变更 1：加用户系统（登录界面+注册+忘记密码）
- **原范围**：Phase 0 无用户系统，管理台单密码鉴权
- **变更后**：Phase 0 加用户登录界面，支持注册和忘记密码
- **影响**：
  - 需要用户表（users: id, username, password_hash, email, created_at, role）
  - 需要注册接口、登录接口（JWT）、忘记密码功能
  - 前端需要登录页、注册页、忘记密码页
  - 角色区分：admin（管理台）、user（学习端）
  - 账户：admin/123456、user25/123456（用户提供）
  - 忘记密码需要邮件发送或安全问题机制
- **复杂度增加**：中高（新增3个前端页面 + 4个后端接口 + 用户表 + 邮件/安全机制）

### 变更 2：加 PPT 课件支持
- **原范围**：Phase 0 支持 Markdown + PDF 课件
- **变更后**：加 .pptx 格式支持
- **影响**：
  - 需要 python-pptx 库提取 PPT 文本
  - PPT 提取质量不如 Markdown（结构信息可能丢失，按页分割）
  - 素材扫描模块增加 .pptx 识别和文本提取
- **复杂度增加**：低（python-pptx 成熟，提取文本简单）

### 变更 3：素材更新功能
- **原范围**：方案B 已包含"重新扫描"能力
- **变更后**：明确要求支持更新（替换文件→重新扫描→更新数据库缓存）
- **影响**：
  - 架构师方案 B 已设计了此流程（"用户替换目录下文件→管理台点重新扫描→元数据与缓存刷新"）
  - 需要明确：更新时正在进行的 AI 会话怎么处理（建议提示用户刷新会话）
- **复杂度增加**：低（方案 B 原有设计的显式确认）

### 变更 4：RAG 语义检索（待确认）
- **原范围**：Phase 0 不上 RAG，用时间窗截取
- **变更后**：用户认为 RAG 切块有必要，语义匹配更好
- **技术澄清**：
  - 字幕文件（VTT/SRT）**包含时间码**，时间窗截取可行且精准
  - 课件（Markdown/PDF/PPT）**没有时间码**，确实需要语义匹配
  - 最优方案：字幕用时间窗截取（精准）+ 课件用 RAG 语义检索
- **影响**：
  - 需要向量库（Chroma）+ embedding 模型（bge-m3 或云端 API）
  - 需要分片策略（逐字稿按时间窗、课件按章节/页）
  - context_builder 需要融合时间窗+语义检索双路召回
  - 工程量增加 3-5 人天
- **复杂度增加**：高（向量库+embedding+分片+检索调优）

## 追加变更（变更 #1 之后补充）

### 变更 5：集成 Whisper 自动生成字幕
- **日期**：2026-08-23
- **触发原因**：用户询问"有什么软件可以自动转换视频为字幕"，暴露"用户可能只有视频没有字幕文件"的痛点
- **原范围**：Phase 0 要求用户自备字幕文件（VTT/SRT）
- **变更后**：Phase 0 后端集成 OpenAI Whisper，用户放入视频后自动生成字幕
- **用户确认**：集成 Whisper 本地生成
- **影响**：
  - 后端需要集成 openai-whisper（pip install，Python 生态天然适配 FastAPI）
  - 需要异步任务处理（字幕生成耗时长，不能阻塞请求）
  - 模型选型：tiny/base/small/medium/large，中文建议 medium+，CPU 可跑但慢
  - 模型文件首次下载（medium 约 769MB，large 约 1.5GB）
  - materials 表需要加字幕生成状态字段（subtitle_status: pending/generating/ready/error）
  - 素材接入流程变化：放入视频 → 自动生成字幕 → 生成完成后可用
  - 工程量 +2-3 人天
- **复杂度增加**：中（异步任务+模型管理+进度反馈）

### 变更 6：字幕=逐字稿（数据模型简化）
- **日期**：2026-08-23
- **触发原因**：架构师设计里"字幕"和"逐字稿"两个词造成混淆
- **原范围**：字幕文件用于显示，逐字稿是独立文件（完整授课文本）
- **变更后**：字幕文件就是逐字稿，不分两个文件。subtitle_path 就是逐字稿路径，时间窗截取直接从字幕文件取
- **影响**：
  - materials 表不需要单独的 transcript_path 字段
  - context_builder 的时间窗截取直接从 subtitle_path 对应的 VTT 文件取文本
  - 简化了数据模型和素材接入流程
- **复杂度降低**：简化（减少一个文件维度）
