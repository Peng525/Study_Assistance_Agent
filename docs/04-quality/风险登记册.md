# 风险登记册 v2（按升级后 Phase 0 范围重评）

> 日期：2026-08-23
> 依据：提议书 V1.2 原风险登记册 + 需求评审报告 F1/F4/F5
> 变更原因：Phase 0 范围从"纯演示原型"升级为"可直接拿来用"，所有"原型可接受"风险结论需按真实使用场景重评

---

## 重评原则

- 风险场景从"演示中短课程样本"改为"用户真实长课程 + 自备素材"
- "原型可接受"不再作为风险缓解理由
- 新增风险：管理台、可换素材承载（原提议书无此内容）

---

---

## 核心结论

升级后 Phase 0 的**高风险项从 3 个增加到 4 个**，且新增的 R-05（Token超限）、R-07（管理台安全）、R-08（素材承载）都是"不解决不能进开发"的致命项。这印证了需求评审报告的判断：**不要带这些风险进开发，先补方案再动代码**。
