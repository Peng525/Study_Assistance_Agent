# .workbuddy 与 .codex 的配置同步说明

> 建立时间：2026-09-04 17:36
> 对应 commit：`c442a08`
> 同步方向：**`.codex` 是源，`.workbuddy` 是目标，单向同步**

## 为什么有两套

项目里并存两套 agent/hooks 配置，服务于不同的宿主：

| 配置 | 宿主 | 格式 | 状态 |
|---|---|---|---|
| `.codex/` | Codex | TOML + PowerShell | **权威源**，本文件不改它 |
| `.workbuddy/` | WorkBuddy | JSON + Skill(Markdown) | 同步目标 |

`.codex` 里的定义在 WorkBuddy 里读不懂（不认 TOML agent、不认 `hooks.json`），所以做了这次同步。**两边内容必须保持一致**，否则会出现「Codex 里是新版、WorkBuddy 里是旧版」的漂移。

## 同步了什么

### 1. 逐字节镜像（改动 .codex 后需重新复制）

| 目标 | 源 |
|---|---|
| `.workbuddy/config.toml` | `.codex/config.toml` |
| `.workbuddy/hooks.json` | `.codex/hooks.json` |
| `.workbuddy/agents/*.toml`（6 个） | `.codex/agents/*.toml` |
| `.workbuddy/agents/production-backup/` | `.codex/agents/production-backup/` |

这几份只是**资产镜像**，让两边文件结构对齐、便于对照。WorkBuddy 本身不加载 TOML。

### 2. 格式转换（提示词改了要手工同步两边）

| 目标 | 源 |
|---|---|
| `.workbuddy/skills/requirement-reviewer/SKILL.md` | `.codex/agents/requirement-reviewer.toml` |
| `.workbuddy/skills/prd-writer/SKILL.md` | `.codex/agents/prd-writer.toml` |
| `.workbuddy/skills/architect/SKILL.md` | `.codex/agents/architect.toml` |
| `.workbuddy/skills/code-reviewer/SKILL.md` | `.codex/agents/code-reviewer.toml` |
| `.workbuddy/skills/tester/SKILL.md` | `.codex/agents/tester.toml` |
| `.workbuddy/skills/release-manager/SKILL.md` | `.codex/agents/release-manager.toml` |

这 6 份是**真正在 WorkBuddy 里生效**的版本：把 TOML 的 `developer_instructions` 转成了 Skill 正文，让 WorkBuddy 能调用这些角色。

⚠️ **改提示词时两边都要改**。只改一边会造成同一角色在 Codex 和 WorkBuddy 下行为不一致。

### 3. 钩子脚本：复用，不复制

`.workbuddy/settings.json` 的 6 个事件直接指向 `.codex/hooks/*.ps1`，**脚本没有复制到 `.workbuddy/`**。

这么做是为了避免双份维护——改脚本只改 `.codex/hooks/` 一处。代价是：`.codex` 若被删除或改名，WorkBuddy 的钩子会全部失效。

当前挂载的钩子（7 条）：

| 事件 | 脚本 | 作用 |
|---|---|---|
| PreToolUse (Bash) | `demo-pre-commit-guard.ps1` | 提交门禁检查 |
| UserPromptSubmit | `requirement-change-detector.ps1` | 识别需求变更 |
| SessionStart | `session-restore.ps1` | 恢复项目记忆 + 注入接手文档速览 |
| SubagentStart | `demo-subagent-context.ps1` | 注入 subagent 执行契约 |
| PreCompact | `pre-compact-save.ps1` | 压缩前保存状态 |
| PostToolUse (Bash/Edit/Write) | `demo-post-code-check.ps1` | 代码基础检查 + 重置 QA 门禁 |
| PostToolUse (Bash/Edit/Write) | `demo-handover-reminder.ps1` | 提醒更新接手文档 |

命令用 `bash -c '... "$CODEBUDDY_PROJECT_DIR/..."'` 包装，是为了让环境变量在 bash 里展开——直接交给 PowerShell 会因路径含空格（`vibe coding`）和变量语法差异而失效。

## 改动后要做什么

1. **改了 `.codex/agents/*.toml`** → 重新复制到 `.workbuddy/agents/`，并同步更新对应的 `SKILL.md`
2. **改了 `.codex/config.toml` 或 `hooks.json`** → 重新复制到 `.workbuddy/`
3. **改了 `.codex/hooks/*.ps1`** → 什么都不用做（WorkBuddy 直接引用）
4. **改了 `.workbuddy/settings.json` 或新增了 skill** → 会改变 `snapshot_hash`，**QA 门禁双 flag 会失效，commit 前必须重跑**

## 遗留：`.codebuddy/`

`.codebuddy/hooks/` 下还有 5 个 8-23 的 bash 旧钩子（`*.sh`），依赖 `jq`，在 Windows 上大概率跑不起来。本次按你的要求**没有删除**，等确认后再处理。现在 `.workbuddy/settings.json` 已不再指向它们，所以不影响运行。
